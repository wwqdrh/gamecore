# 独立游戏剧本文档模板

独立游戏（原型/小型规模）的行业通用剧本结构。各节可按项目取舍，但顺序与
粒度建议保留——前三节定"世界与谁"，中间三节定"发生什么、玩家做什么"，
后三节定"怎么讲、怎么落地"。

## 0. 灵感追问（从零生成时）

信息不足时最多问 1~2 轮：

1. 游戏类型与核心玩法（玩家主要在玩什么）
2. 期望的核心体验/情绪（爽、压抑、治愈、悬疑…）

其余（题材、世界观、人物）由撰写者补全并标 `[假设]`。

## 1. 一句话梗概（Logline）

一句话说清「谁 + 在什么世界 + 面对什么冲突 + 做什么」。
示例：`一个卡在入门瓶颈的宗门弟子，为寻找失踪的父亲踏入封印秘境，
却在层层突破中揭开宗门与魔道百年恩怨的真相。`

## 2. 世界观设定

- **时代与舞台**：时代氛围、核心地理（每张地图一段：名称、景观、
  在剧情中的定位）。地图名应与项目实际地图资源对应。
- **规则体系**：世界的核心规则（修炼/魔法/科技），**必须与项目成长数值
  体系一致**（等阶/等级命名照抄定义表）。
- **核心冲突**：驱动主线的根本矛盾（人 vs 人 / 人 vs 环境 / 人 vs 自我），
  以及这个冲突为何"只能由主角解决"。
- **基调**：整体情绪与叙事风格（热血/黑色/治愈），影响全部对白语气。

## 3. 人物设计

每个人物一张卡片，字段统一：

| 字段 | 说明 |
|---|---|
| 姓名/称谓 | 世界观内自洽的命名 |
| 身份 | 种族/阵营/职业/与主角的关系 |
| 性格 | 2~3 个关键词 + 一句行为特征 |
| 动机 | 想要什么、为什么——**反派动机要能自圆其说** |
| 外形 | 视觉记忆点（立绘/模型参考） |
| 成长弧线 | 从 A 状态到 B 状态的转变（主角必须有；配角可省） |
| 玩法绑定 | 该人物在玩法中的载体（NPC 对话/商人/任务发布/Boss） |

人物分层：

- **主角**：1 名。动机要同时有「外部目标」（找父亲/复仇）与「内在缺口」
  （被认可/自我怀疑），弧线 = 内在缺口的填补。
- **核心配角**：2~4 名。各绑定一个玩法系统（引导者绑定教程、商人绑定经济、
  挚友绑定支线）。
- **反派**：1 名主反派 + 若干爪牙。主反派在第一幕就要"露影子"。
- **NPC 群像**：功能性 NPC（铁匠/药师/守卫），各一句人设即可，成表。

最后画一张**关系网**（文字版）：`甲 —(师徒)— 乙 —(旧怨)— 丙`。

## 4. 剧情主线

### 三幕结构（原型/线性叙事）

- **第一幕·起**（约 25%）：日常与破绽——展示世界与主角缺口，事件打破
  日常，给出外部目标。
- **第二幕·承**（约 50%）：深入与代价——目标推进、能力成长、中点反转
  （真相揭露/盟友背叛），局势恶化到最低点。
- **第三幕·合**（约 25%）：决断与和解——最终对决，外在冲突解决 +
  内在缺口填补（弧线完成），留一角余味。

### 章节制（开放/单元叙事）

每章一张 beat 表：`章节 | 玩家等阶/等级 | 关键事件 | 解锁内容 | Boss/里程碑`。
原则：**剧情推进与能力解锁交替**，每章结尾有钩子。

### 关键节点（Beat Sheet）

把三幕拆成 8~15 个 beat，每个 beat 一行：
`序号 | 幕 | 事件 | 场景/地图 | 涉及人物 | 玩家行为`。
beat 是后续任务设计与对话脚本的索引，必须具体到"玩家此刻在做什么"。

### 结局（可选分支）

多结局时列出：达成条件（flag/选择）→ 结局描述 → 与核心冲突的呼应关系。
单结局则写明"余味镜头"。

## 5. 支线剧情

每条支线 3~5 行：名称 | 发布人 | 触发条件 | 简述 | 与主线的关系
（补充世界观/深化配角/纯奖励）。独立游戏支线贵精不贵多，每条都要
"讲世界的一个切面"。

## 6. 任务设计

任务表（表格形式），字段：

| 字段 | 说明 |
|---|---|
| 任务 ID | 项目内唯一，`main_xxx` / `side_xxx` 前缀 |
| 类型 | 主线/支线/日常 |
| 发布人/触发 | 谁、在哪张地图、什么条件触发（对话/拾取/进入区域） |
| 目标 | 一句话玩家可读的目标描述 |
| 流程 | 分步 checklist（每步对应可实现的玩法动作：对话/采集/击杀/传送） |
| 奖励 | 道具（引用定义表 id）/经验/解锁 flag |
| 叙事作用 | 该任务讲了什么故事 |

校验：流程里每一步都要能用项目现有能力实现（对话触发器、等阶经验、
道具表），不能实现的列入「需新增系统」清单。

## 7. 关键对话脚本

挑 3~6 个最重要场景写全对白。若项目有对话系统（timeline/对话框），
**用项目语法写**，可直接落成脚本资源；否则用
`角色名：（动作）对白` 的剧本体。要求：

- 每句不超过一行显示长度（对话框 2 行内）。
- 选项分支最多 3 项，且都能收回主线（独立游戏不鼓励死分支）。
- 语气符合第 2 节基调与人物卡片。

## 8. 叙事与玩法结合点

列出"叙事靠什么玩法承载"：成长体系即剧情阶梯（突破=章节）、
收集品即碎片化叙事（残图/信件）、任务即单元剧。每条注明玩法载体。
没有玩法承载的剧情内容一律删掉或降级为可选项。

## 9. 文案规范

- **命名规范**：人名/地名/功法/丹药的构词规则（如丹药=材料意象+剂型）。
- **称谓表**：各阵营/辈分间的互相称呼（师尊/道友/尔等）。
- **禁用与偏好**：语气词、标点、术语首现需注释等。
