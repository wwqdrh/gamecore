# GDD 文档模板

按此结构输出，方括号为占位说明，写文档时删除。每个一级章节由对应策划角色撰写。

```markdown
# 《<游戏名>》游戏设计文档

| 项 | 内容 |
|---|---|
| 版本 | v0.1（初稿） |
| 日期 | YYYY-MM-DD |
| 状态 | 立项讨论稿 |
| 规模 | 原型 / 小型 / 中型 |

---

## 一、项目概述（主策划）

### 1.1 一句话定位
<用一句话说清"什么类型 + 玩家做什么 + 体验卖点"，例：一款以时间倒流为核心机制的 2D 平台解谜游戏>

### 1.2 基本信息表
| 项 | 设定 |
|---|---|
| 游戏类型 | <如：肉鸽卡牌 / 模拟经营 / 平台解谜> |
| 目标平台 | <PC / 手机 / Web> |
| 单局/会话时长 | <如：单局 15~20 分钟> |
| 目标玩家 | <一句话画像> |

### 1.3 核心体验支柱
玩家体验的三条支柱，后续所有设计决策向它们对齐：
1. **<支柱名>**：<一句话解释玩家在什么时刻感受到它>
2. ...
3. ...

### 1.4 竞品参照
| 参照游戏 | 借鉴点 | 差异点 |
|---|---|---|
| <游戏A> | <机制/节奏> | <我们的不同> |

### 1.5 风险与范围
- <技术/设计/内容量风险各 1~2 条，附应对思路>
- 最小可玩版本（MVP）范围：<明确原型要验证什么>

---

## 二、核心玩法（玩法策划）

### 2.1 核心循环
用循环图（文字箭头式）描述玩家一分钟~一个 session 内不断重复的行为闭环：

```
<行为A> → <行为B> → <反馈/奖励C> → <驱动回到A的钩子>
   ↑______________（成长/解锁让下一轮更有趣）______________↓
```

并逐节点说明：玩家在该节点做什么、得到什么反馈、为什么愿意进入下一节点。

### 2.2 核心机制
游戏赖以成立的 1~3 个机制，每个按"规则 + 为什么有趣"写：
- **<机制名>**：
  - 规则：<触发条件 → 过程 → 结果，可执行级描述>
  - 有趣在哪：<对应 1.3 的哪条体验支柱>

### 2.3 类型规则体系
按游戏类型写清对应规则（肉鸽/卡牌类写构筑与战斗，经营类写生产链与经济，
解谜类写谜题要素与提示规则……）。每条规则给数值框架（不定明细）：
- **构筑规则**（示例）：<卡池结构 / 取舍约束 / build 成型路径>
- **战斗规则**（示例）：<回合/实时结构、行动次序、伤害公式框架、胜负条件>
- **经济规则**（示例）：<资源种类、产出/消耗点、防止通胀的手段>

### 2.4 失败与成长
- 失败条件与失败反馈（失败也要有趣）
- 玩家跨局/长线成长的形式（元进度、解锁、熟练度）

---

## 三、系统设计（系统策划）

### 3.1 系统清单
| 系统 | 一句话职责 | 优先级 | 依赖 |
|---|---|---|---|
| <战斗系统> | <…> | P0 | <无> |
| <构筑系统> | <…> | P0 | 战斗 |

（原型级项目 ≤6 个系统；P0 = MVP 必需，P1 = 首个可玩版本，P2 = 后续）

### 3.2 各系统规则要点
每个 P0/P1 系统一小节：
**<系统名>**
- 职责与边界：管什么、不管什么
- 数据结构：<核心实体与字段框架，如 卡牌{id, 费用, 效果标签}>
- 流程规则：<主要流程的步骤描述（进入→操作→结算→退出）>
- 与其他系统的接口：<消费谁的输出、输出给谁>

### 3.3 界面与功能结构
```
主界面
├── <界面A>        # 入口：<从哪进>；核心操作：<…>；出口：<去哪>
├── <界面B>
│   ├── <子页/弹窗>
│   └── <子页/弹窗>
└── <设置/退出>
```
- 每个界面说明：入口、核心操作、出口、承载的系统数据。
- HUD 常驻元素单独列出（血条/资源/提示区）。

### 3.4 关键流程走查
挑 2~3 条玩家主路径做端到端走查（新玩家首次进入、一次完整战斗/回合、
一次存档退出），验证系统与界面闭环无断点。

---

## 四、世界观与文案（文案策划）

### 4.1 世界观设定
- 世界背景：<时代/舞台/核心设定，300 字以内>
- 核心冲突：<驱动玩法目标的叙事矛盾>
- 世界观与玩法的结合点：<叙事如何解释核心机制，如"时间倒流"的世界观如何包装在机制里>

### 4.2 主要角色/阵营
| 名称 | 定位 | 一句话人设 | 与玩法的关系 |
|---|---|---|---|

### 4.3 文案规范
- 命名规范：<地名/道具/技能的构词规则，各给 2~3 个示例>
- 语气基调：<整体文风一句话 + 一段示例文案>
- 敏感规避：<平台审核/年龄分级相关的用词红线>

### 4.4 教程文案
新玩家前 N 分钟的引导脚本框架：
| 步骤 | 玩家操作 | 引导文案（示例） |
|---|---|---|
| 1 | <…> | <"…" > |

### 4.5 道具/物品描述示例
给 3~5 个代表性条目的完整描述示例（名称/品质/描述文案/风味句），
作为批量产出的格式样板。

## 五、待讨论事项（主策划收束）
尚未定稿、需要下一轮讨论拍板的问题清单：
1. [ ] <问题 + 当前倾向方案>
2. [ ] ...
```

## 使用说明

- 四个章节必须交叉引用（如系统设计的界面要能支撑核心循环的每个反馈节点），
  冲突处标注 `[决策]` 并给主策划结论。
- 规模决定深度：原型级项目可省略 4.3 之外的大部分 4.x 小节，但 1.3 / 2.1 / 3.1
  / 4.1 四节永远必写。
